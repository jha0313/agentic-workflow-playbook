AI에게 칸이 아니라 절차 전체를 넘기는 6단계 루프

AI가 실행을 싸게 만들었다. 그래서 가치도, 고통도 전부 검증으로 옮겨갔다.
버티는 워크플로우는 검증을 독립된 외부 단계로 다룬다 — 작업한 에이전트가 자기 결과를 채점하게 두지 않는다.

불변식 — 이 한 줄이 나머지 전부를 지탱한다
5번 검증의 바깥 층(5-b)은 외부여야 하고,
작업을 수행한 에이전트에게 위임할 수 없다.

기획에선 사람 + 출처 대조. 개발에선 전후 대조(diff) + 기준선 비교.
나머지 전부가 속도가 나오는 자리다.

이 루프를 굴리는 사람 — 조율자

조율자(orchestrator)는 흐름을 소유하되 직접 일하지 않는다. 사람이 조율자여도 되고 에이전트가 조율자여도 된다. 다만 조율과 실행은 섞지 않는다.

개발·기획·조사·보고서 어디에나 같은 모양. 특정 도구에 묶여 있지 않다.

위험 신호: 맡겼는데 내가 직접 할 때와 시간이 비슷하거나 더 든다. — 이게 이 상태의 진단명이다.

프레임

6단계 루프 — 0 맥락 → 1 의도 → 2 스펙 → 3 분해 → 4 구현 → 5 검증 → 6 개선

단계를 누르면 아래에 상세가 열린다. ← → 로 이동. 오른쪽 스위치로 개발 / 비개발 재료를 나란히 본다.

5번은 두 층이다

대부분의 실패는 이 둘을 하나로 뭉갤 때 생긴다. 싸고 자동인 층과 비싸고 판가름이 나는 층은 실패했을 때 되돌아가는 곳이 다르다.

기계5-a 게이트

성격
싸다. 자동. 결정적(deterministic) — 같은 입력이면 같은 답. 매 조각마다 돈다
무엇
테스트 · 타입 · 린트 · 완결성 스캔 · 출처 확인
실패 시
그 조각만 재시도. 상한 K=3~6. 넘으면 멈추고 보고
함정
통과해도 맞다는 뜻이 아니다. 초록불은 필요조건이지 충분조건이 아니다

외부5-b 외부검증

성격
비싸다. 최종 판정(ground truth). 사람·다른 모델의 판단이라 매번 같지는 않다
무엇
사람 리뷰 / 다른 모델 교차검증 / 전후 대조 / 기준선 비교
실패 시
2번(스펙)으로 되돌아간다. 다시 쓰는 걸로 때우지 않는다
함정
작업한 쪽에 맡기는 순간 무의미해진다

AI → AI → AI → 사람. 사람이 보던 지표를 문서화해 넘기면 사람 시간이 확 줄어든다. 교차검증은 필수 — 모델마다 학습·추론이 다르다. 그리고 사람은 taste만 본다: UI·UX · 비즈니스 맥락 · 디자인 · 아키텍처.

한계도 말할 것: 두 에이전트가 같은 잘못된 전제를 공유하면 상호 검토도 실패한다. 평가 기준 자체도 감사 대상이다.

얼마나 검증할지는 위험도로 정한다

자동화 사다리

지금 어디에 서 있나 — 사람의 위치

같은 루프 위에서 사람이 서 있는 칸만 달라진다. 단계를 고르면 위 다이어그램의 👤 위치가 바뀐다.

한 칸 올라가는 조건은 하나뿐이다. 5-a를 객관적 지표로 정의해서 에이전트가 대신 수행할 수 있게 만들었을 때. 건너뛰고 바로 맨 위로 가면 장애가 난다. 순서대로 올라간다.

설계 원칙

버티는 워크플로우가 공유하는 7가지

그리고 투자 배분을 뒤집어라

0번(맥락)과 5번(게이트)에 시간을 몰고, 4번(실행)은 짧게 끝난다. 레거시를 옮길 때 테스트 만드는 데 몇 주, 실제 이관은 며칠 — 이게 정상적인 배분이다.

레거시의 본질은 코드가 아니라 비즈니스 컨텍스트 부족(0번 결핍)이다. 그래서 답이 다시 0번으로 돌아온다.

한 번만 하고 버릴 일

6번의 되먹임이 회수될 기회가 없다.

위험 신호: 맡겼는데 내가 직접 할 때와 시간이 비슷하거나 더 든다.
그러면 루프가 잘못된 게 아니라 0번이 비어 있거나 5-a가 정의돼 있지 않은 것이다. 그 둘을 먼저 보라.

넣기 전에 확인할 것

사내 자료를 에이전트에 넣기 전에 회사 정책을 확인한다. 0번 파일에 기밀 · 개인정보 · 자격증명을 담지 않는다. 담아야 한다면 참조 위치만 적고 값은 넣지 않는다.

에이전트가 만든 스크립트와 스킬은 실행되는 코드다. 읽지 않고 돌리지 않는다. 남이 만든 것을 그대로 가져다 쓸 때는 특히.

5-b를 생략한 결과물을 외부에 내보내지 않는다. 초록불은 통과의 증거가 아니다.

드롭인 조율자 템플릿

복사해서 붙여넣는다 — 맨 아래 6칸만 채우면 시작된다

에이전트 대화창에 통째로 넣어도 되고, 팀 저장소에 두고 에이전트가 읽게 해도 된다. 후자를 권장한다 — 팀이 같이 고쳐 나가는 0번 자산이 된다.

역할: 너는 조율자(ORCHESTRATOR)다. 흐름만 관리하고, 직접 실행하지 않는다.

            체크리스트로 바꿀 수 없는 항목은 스펙이 아니다 → 1번으로 되돌린다.

[3] 분해  — N개 조각으로 쪼갠다. 조각마다 의존성과 성공 판정을 붙인다.
            한 조각 = 서브에이전트 한 세션에 들어가는 크기.
            독립 조각은 병렬로 표시한다. 사소하지 않으면 계획 리뷰를 한 번 넣는다.

[4] 구현  — 조각마다 서브에이전트를 띄운다. 프롬프트는 자족적으로 —
            앞 단계 결과를 본문에 통째로 넣는다. 중간에 되묻게 하지 않는다.
            독립 조각은 동시에 띄운다.

[5] 검증  — 5-a 게이트(싸고 자동): <게이트 명령 또는 체크리스트>
              실패 → 그 조각만 재시도. **상한 K=<3~6>. 넘으면 멈추고 보고한다.**
              통과해도 "맞다"는 뜻이 아니다. 반드시 5-b로 간다.
            5-b 외부검증(비싸고 최종 판정): <외부 심판>
              작업을 수행한 에이전트에게 채점을 맡기지 않는다.
              실패 → **2번(스펙)으로 되돌아간다.** 다시 쓰는 걸로 때우지 않는다.

[6] 개선  — 산출물을 낸다. 무엇을 어떻게 만들었는지 기록한다.
            드러난 실패 패턴과 새 규칙을 0번 파일에 되먹인다.
            파이프라인 중간이면 "이 단계 완료"는 체크포인트일 뿐이다 —
            나에게 돌려주고 다음 단계를 기다린다.

규칙
- 모든 재시도 루프에 상한을 둔다.
- 서브에이전트에는 맥락을 전부 준다.
- 독립 단계는 병렬로 돌린다.
- 작업자가 자기 정확성을 채점하게 두지 않는다.
- 0번에 없는 규칙을 지어내지 않는다. 모르면 멈추고 묻는다.
- 확실한 것과 추측을 구분해서 말한다. 추측을 사실처럼 쓰지 않는다.
- 단계를 건너뛰지 않는다. 각 단계 끝에서 현재 위치를 한 줄로 보고한다.

이 루프는 스킬 한 장으로 고정된다

5 검증 — 초보 스킬에 없는 것

5의 반려 + 6 개선
